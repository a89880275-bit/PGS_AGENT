# 요구사항 추적

[2단계 v2.3 우선 명세](source/PGS_CODEX_PHASE_2_v2.3.md)와 [3단계 v2.3 상세 명세](source/PGS_CODEX_PHASE_3_v2.3.md)를 적용하고 비충돌 0~2단계 요구사항을 유지한다. [v2.1 전체](source/PGS_REQUIREMENTS_v2.1.md) 및 [0~1단계 별첨](source/PGS_CODEX_PHASE_0_1_v2.1.md)은 당시의 기준을 보존한다.

| 영역 | 현재 적용 |
|---|---|
| PDF 저장 | Agent PC의 비공개 UUID 경로. 중계 서버는 WSS에서 인증된 요청의 바이트를 일시 처리 |
| 등록 | 수동 합성 파일과 Mock 환자 확인. Agent 시작형 HTTPS JSON 메타데이터와 WSS |
| PostgreSQL | Agent, 소유 요청, 정책, 문서, 테스트 인증 해시 및 처리 상태. PDF와 내부 경로 제외 |
| 보관 | 30일 기본, 1~90일, 링크 ≤ 보관. 종류별 정책 우선. 확정된 기한과 과거 7일 문서 보존 |
| 조회 | CSPRNG 링크, HMAC 생년월일, 문서 세션, PDF.js 및 WSS 다운로드. 가상 환자와 로컬 프로필에서 검증 |
| 삭제 | 기한 즉시 접근 차단, 시험 시계·수동 삭제·오프라인 처리·동기화. 운영 스케줄러는 6단계 |
| 배포 | Netlify 정적 화면 후보와 별도 상시 중계 서버. 이번에는 루프백 PoC |

일 1,000건 × 85KB × 30일은 2.55GB다. 30% 여유를 포함하면 3.315GB, 90일에는 9.945GB다. 내부 여유 20GB 권장 기준에는 대기열·로그·백업을 별도로 고려한다. 월 30,000건에 평균 2회 조회할 때 중계 PDF 송신량은 약 5.1GB/월이다.
신규 파일의 기본 환자번호는 8자리다. 합성 샘플 파일명은 0100111120261124a01.pdf다. 요구사항 원문에 있는 7자리 예시는 당시 기준이다.
