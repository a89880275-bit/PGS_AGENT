# 2단계 자체 검증

| 검증 | 대상과 판정 |
|---|---|
| 기존 0~1단계 | 파서·앞자리 0·윤년, Oracle Mock, 요청 재시도, 독립 발급, 만료·잠금·삭제, Edge의 Agent/관리자/환자 업무 흐름 |
| PostgreSQL | PGlite PostgreSQL 엔진에서 001/002 반복 적용. 기간 제약, 기본/종류별 1·30·90일, 과거 7일 기한 유지, 새 문서 30일, 재발급 기한 보존 |
| SQLite/Storage | UUID 사본의 해시 일치, 재개, 경로 이탈·junction·내용 변조 차단, 정확한 기한, 삭제 실패·재실행·동기화 대기, 사용률 지표 |
| Agent/Relay | 별도 프로세스와 로컬 TLS, 정상·중복·응답 유실·재시작, 파일명/날짜/환자/형식/크기 오류, 파일 아닌 JSON 메타데이터, 환자/관리자 인증, 중계 전송 해시와 no-store, 오프라인·504·취소 및 삭제 재동기화 |
| 브라우저 | Edge의 Agent 수동 저장, 관리자 기본·종류별 정책 및 미리보기, 320px 환자 PDF.js·다운로드 |
| 용량/부하 | 30,000건 메타데이터, 테이블/인덱스 크기. 85KB 합성 PDF 1,000건 등록 및 동시 10건 다운로드, 지연·RSS·오류 수 기록 |

테스트의 임시 데이터는 `.local/`에 둔다. 실행은 [README](../README.md)를 따른다. PostgreSQL 17 Docker의 서버 구동·드라이버 검증, 실제 배포 프록시·CDN의 캐시·버퍼 비활성화, 병원 방화벽 및 장비 검증은 환경 준비 후 진행한다. 환자 운영 인증은 3단계다.

## 로컬 실측

- 소스 검사, React 번들, TypeScript 검사, 단위 테스트 8건 및 기존·2단계 Edge 흐름을 통과했다.
- PostgreSQL 엔진에 30,000건을 적재했다. 문서 테이블 약 8.48MB, 인덱스 약 4.54MB, 전체 약 13.05MB였다. 인증 테이블·배포 환경의 백업은 별도다.
- 약 85KB 합성 PDF 1,000건을 10건씩 묶어 등록했다. 등록 오류는 0건, 전체 36.9초, 등록 p95는 362ms였다. 동시 다운로드 10건은 모두 바이트 해시가 일치했고 p95는 149ms였다. 관측 최대 RSS는 중계 약 356MB, Agent 약 155MB였다.
- 이 수치는 로컬 단일 PC와 PGlite로 측정했다. 외부 네트워크나 배포 프록시 조건을 포함하지 않는다.

## 3단계 자체 검증

- 실행 명령은 node tests/phase3-migration.mjs, node tests/phase3-integration.mjs, node tests/phase3-browser.mjs다. Windows 오프라인 환경 설정은 README를 참조한다.
- PostgreSQL 003와 SQLite 002를 적용 후 재실행했다. 기존 7일 기한, 세션/토큰 문서 일치 제약, 암호화된 링크 읽기 및 틀린 키 거부를 확인했다.
- HTTPS/WSS 테스트로 토큰 무작위성, 같은 요청 재시도, 등록 응답 유실, Agent 재시작, 미인증·다른 문서·다른 origin 차단, GET/HEAD 무소모, 동시 실패 5회, 30분 잠금, IP 속도 제한, 15분 절대 만료·재인증·로그아웃, 720시간 경계, 재발급·폐기를 확인했다.
- 동시 10건의 원본 해시, 오프라인·재연결, 첫 응답 시간초과, 중간 연결 종료 및 버퍼 해제, 데이터 파일·WAL·로그의 원문 미잔류를 확인했다.
- 실기기 Android/iOS·카카오 인앱, 설치형 PostgreSQL 17, 운영 프록시와 보호 키 저장소는 검증 환경 승인 후 진행한다.
