# 보안 및 운영 승인

로컬 PoC는 127.0.0.1에만 바인딩한다. Agent는 신뢰한 루프백 인증서로 TLS를 검증하며 서버는 Agent ID·Bearer·등록 소유권을 확인한다. WSS FETCH 권한증표는 대상 Agent·문서·요청·기한에 결합해 서명하고 한 번만 사용한다. 임의 명령이나 경로는 받지 않는다. 테스트 인증이 켜진 운영 실행은 시작 단계에서 차단한다.

원본은 Agent 내부의 비공개 경로에 저장한다. UUID와 SQLite로만 경로를 해석하고 경로 경계, symlink·junction, 파일 동일성·크기·해시를 확인한다. Agent PC의 실제 서비스 계정 ACL, BitLocker, 디스크 복구 및 물리 접근 보호는 운영 준비에서 검증한다. HIS 소유 원본에는 별도 승인된 삭제 책임이 필요하다.

환자 세션과 관리자 미리보기에는 역할·문서 확인을 적용한다. 이번 관리자 세션은 루프백 시연용이다. 테스트 환자 링크와 생년월일 인증은 운영용과 분리한다. 생년월일 원문 대신 문서별 HMAC을 사용한다. no-store, no-referrer, 검색 방지를 적용하며 PDF/자격증명·요청 본문·토큰을 로깅하지 않는다.

운영 전 중계의 TLS, 상호 인증/회전, 방화벽, 스왑·메모리 덤프·APM, CDN/프록시 응답 버퍼 및 캐시 비활성화, 위탁처리/소재지를 승인한다. Agent 상시 가동·UPS·복구, 고령 사용자의 추가 인증 및 대리인 정책도 확인한다.
## 3단계 보안 경계

신규 링크는 32바이트 CSPRNG, 세션은 32바이트 불투명 난수다. 중계 DB에는 SHA-256 해시만 기록한다. Agent에만 AES-256-GCM 봉인 키를 전달하고 문서·세대를 부가 인증 데이터로 결합한다. 로컬 키 파일에는 서비스 계정 ACL을 적용할 수 있고 운영 키 보관 방식은 승인 후 연결한다.

생년월일은 Agent가 가상 환자 어댑터에서 확인한 뒤 문서 UUID·salt·버전을 결합한 HMAC으로 변환한다. 이전 버전 검증 키는 `PGS_BIRTH_KEYS`로 유지할 수 있다. 유효 문서의 5회 실패는 원자 카운터로 처리하며 30분 잠긴다. 토큰·직접 연결 IP·전체 경계에서 각각 요청 제한을 적용한다. 전달된 IP 헤더는 신뢰하지 않는다.

HTTPS Secure·HttpOnly·SameSite=Strict 쿠키를 사용하고 쓰기 요청은 정확한 동일 origin을 확인한다. 서명된 재인증 쿠키는 해시 참조만 가지며 생년월일 검증이 다시 필요하다. 열람 성공 기록, PDF, 원문 토큰, 세션, 생년월일, 로컬 경로를 중계 로그에 남기지 않는다.
