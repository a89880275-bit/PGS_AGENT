# PGS Codex 개발 지시 — 0단계 및 1단계

기준 문서: PGS_REQUIREMENTS_v2.1.md. 각 단계 프롬프트를 순서대로 입력하고 검증 후 다음 단계로 진행한다.

공통 변경사항: PDF 보관 및 링크 유효기간은 등록 성공 후 7일(168시간)이다. DB 기본값, API 응답, UI 안내, Mock 만료 및 삭제 테스트에 동일하게 적용한다. 기존 30일 설정이나 예시는 제거하고 재발급 시 원래 삭제시각을 초과하지 않는다.

## 0단계 — 프로젝트 기본 설계 및 개발환경

첨부한 PGS_REQUIREMENTS_v2.1.md 전체를 읽고 PGS 환자 모바일 안내문 시스템의 0단계만 구현해줘.

1. 기존 프로젝트가 있으면 먼저 구조와 변경사항을 확인하고 기존 소스를 무단 삭제하지 마. 신규 프로젝트는 TypeScript 모노레포로 구성해.
2. apps/transfer-agent, apps/api-server, apps/admin-web, apps/patient-web, packages/shared, database/migrations, tests, docs 구조를 생성해. Node.js, Express, React, Electron, PostgreSQL, PDF.js 기반으로 설계해.
3. docs/REQUIREMENTS.md, ARCHITECTURE.md, DATABASE.md, API_SPEC.md, SECURITY.md, TEST_PLAN.md, OPEN_ISSUES.md를 작성해. DB/API는 설계까지만 진행해.
4. 파일명 0100111120261124a01.pdf를 잠정적으로 환자번호 7자리, 날짜 8자리, 접미부 3자리로 분석하는 설정형 파서와 단위 테스트를 작성해. 접미부 의미와 환자번호 고정 길이는 미확정으로 표시해.
5. Oracle 환자 조회 어댑터와 Mock 구현을 분리해. 실제 Oracle SQL 테이블/컬럼은 임의로 정하지 마. 내부 Agent API 요청 ID 기반 상태 조회 및 READY 결과 반환 계약을 정의해.
6. 동일 요청 재시도는 동일 결과, 수정본은 새 문서 및 새 링크, 기존 문서 유지 정책을 설계에 반영해. 기존 알림톡 발송은 READY 이후에만 수행하도록 계약을 정의해.
7. 로컬 실행 명령, .env.example, .gitignore, Docker Compose 개발환경 예제를 작성해. 실제 비밀값, 환자정보, 운영 DB 및 Netlify 연결은 금지해.
8. 합성 데이터만 사용하고 기본 빌드, 타입 검사, 파서 테스트를 실행해. 테스트하지 않은 기능은 완료로 표시하지 마.

완료 보고: 프로젝트 구조, 실행 명령, 설계 문서 목록, 테스트 결과, 미확정 항목, 1단계 착수 조건. 0단계 종료 후 추가 지시를 기다려.

## 1단계 — 전체 UI 및 Mock 업무 흐름

0단계 결과와 PGS_REQUIREMENTS_v2.1.md를 검토하고 1단계만 구현해줘. 기존 설계와 완료 기능을 유지해.

### A. 내부 Agent UI (모던 다크)
- 대시보드: 감시 폴더, Oracle/API 연결 상태(Mock), 금일 감지/완료/대기/실패 건수.
- 전송내역: 기간/상태/문서 검색, 환자번호 마스킹, 요청 ID, 등록 상태, URL 발급 상태, 오류 및 재시도 버튼.
- 수동등록: 테스트 PDF 선택, 파일명 파싱 결과, Mock 환자정보 확인, PDF 미리보기, 등록 시뮬레이션.
- 환경설정: 감시 폴더, 파일명 규칙, 접미부 매핑, 내부 API 주소, 재시도 설정. 실제 비밀키 입력/저장 금지.
- 자동 감시와 Oracle 조회는 Mock으로 표시하고 실제 Windows Service 및 운영 파일 감시는 4단계로 남겨.

### B. 관리자 웹 (밝은 업무용 디자인)
- 대시보드: 등록/보관/만료/삭제 건수, 전송 실패 현황. 환자 열람 통계 제외.
- 안내문 관리: 기간, 환자번호, 종류, 상태, 요청 ID, 등록일/만료일, 미리보기, 링크 복사/교체/차단 시뮬레이션.
- 동일 환자의 수정본을 신규 문서로 추가하고 기존 문서가 유지되는 사례 제공.
- 안내문 종류, API 관리, 삭제 관리, 환경설정 화면. 외부 직접 수동등록은 승인된 환자검증 경로 확정 전 비활성 또는 Agent 등록 안내.

### C. 환자 모바일 웹 (밝고 신뢰감 있는 디자인)
- 알림톡 링크 진입 → 생년월일 8자리 확인 → PDF.js 테스트 PDF 조회 → 다운로드.
- 인증 전 환자명, 환자번호, 문서 제목 미표시. 만료, 잘못된 생년월일, 잠금, 장애 화면 구현.
- 큰 글씨/버튼, 320px 이상 반응형, 키보드 접근성, 페이지 이동/확대/축소.
- 모든 인증과 링크는 시연용 Mock이며 실제 보안 기능으로 간주하지 마. 운영 빌드에 Mock 인증이 포함되지 않도록 분리해.

### D. Mock 연동 및 검증
- 파일 감지 → 파싱 → Oracle Mock 조회 → 등록 대기 → READY → 내부 API URL 반환을 시연해.
- 오류 파일명, 환자 없음, Oracle 장애, 전송 실패, 재시도, 수정본 신규 발급, 만료 사례를 합성 데이터로 제공해.
- READY 이전 URL 미표시 및 알림톡 발송 가능 상태 미표시. 실제 알림톡 발송 금지.
- 모든 메뉴와 버튼은 Mock 동작 또는 명확한 비활성 상태로 구현해. 가짜 성공 메시지를 표시하지 마.
- 로컬 테스트 PDF만 사용하고 외부 네트워크/운영 DB 연결 금지. 빌드, 타입 검사, 단위 테스트 및 가능한 UI 테스트를 실행해.

완료 보고: 화면별 실행 경로, 구현 기능, 변경 파일, 테스트 결과, 스크린샷(가능한 경우), 미구현 기능, 2단계 착수 전 확인사항. 승인 없이 2단계로 진행하지 마.
